## 4. Key Technical Decisions

### 4.1 중앙값 피벗 → 통계적 표준 중앙값
**이전**: `Math.floor(length / 2)` — 짝수 개수 시 비대칭 분류
**이후**: `(sorted[mid-1] + sorted[mid]) / 2` — 대칭 분류
**영향**: 경계 아이템의 분류 변경 가능 → 테스트로 검증 완료

### 4.2 감도 분석 Binary Search
`calcSensitivityGrid`에서 해석적 역산 대신 이진 탐색(15회) 사용.
**이유**: 다중 거래처×품목 가중 비례 분배 포함 시 closed-form 해가 복잡. 15회 반복으로 500% 범위에서 0.015% 정밀도 달성.

### 4.3 반품 아이템 분류 전략
음수 수량 아이템은 quadrant 분류에서 제외하되 summary 합산에는 포함.
**이유**: `unitPrice = revenue / quantity` 에서 음수÷음수=양수가 되어 원가 구조 왜곡 방지. 전체 매출/원가 합계에는 정확히 반영.

### 4.4 시나리오 비교 휘발성 설계
React state만 사용, IndexedDB 미저장.
**이유**: CVP 시뮬레이션은 탐색적(exploratory) 특성이 강해 영구 저장보다 세션 단위 비교가 적합.
