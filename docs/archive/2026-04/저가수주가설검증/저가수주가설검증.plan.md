# "저가수주×가동률 = 이익" 가설 검증 모듈 — 최종 개선 계획안 (v2)

## Context

### 배경
건자재사업본부에서 **"물량을 늘리면 고정비 분산으로 단위원가가 낮아지므로, 저가수주해도 가동률이 오르면 전체 이익이 난다"**는 가정이 통용 중. Claude Opus 4.7에게 상황을 설명하고 받은 개발 프롬프트는 **Python/Streamlit 별도 대시보드** 6개 분석 기능을 제안함.

### Opus 4.7 프롬프트 정밀 분석 결과

#### 1) 기술 스택 불일치 — 기각
프롬프트는 Python/Streamlit/Plotly 스택을 제안하나 기존 대시보드는 **Next.js 14 / TypeScript / Zustand / Recharts**.
- `schemas.ts` + `parser.ts`에서 200/501/100/제조원가/표준원가 **5종 파일 이미 파싱 완료**
- Zustand `dataStore`에 `itemProfitability`, `itemCostDetail`, `customerItemDetail`, `manufacturingCost`, `standardCostBook` 전부 저장 중
- `data_loader.py`(Opus 제안) 역할은 이미 존재 → **별도 Python 스택 구축은 이중 유지보수 부담**

#### 2) 기존 기능과 중복 — 3개 기능은 이미 고도화 존재
| Opus Feature | 기존 구현 | 상세 |
|---|---|---|
| F2: CVP BEP 시뮬레이터 | `calcGroupCVP()` (offsetEffect.ts:1113) | 단위 동질 그룹 BEP 수량·매출 계산, 듀얼 CVP 모드(전사 금액/그룹 수량) |
| F4: 증분 분석 | `calcTotalViewSimulation()` (offsetEffect.ts:505) | **3-way 분해**(priceEffect + costEffect + volumeEffect), 항등식 검증, 절대수량/비율 듀얼 입력, 원가 인상 슬라이더(원재료/노무/외주 3축) — Opus 제안보다 **더 정교** |
| 감도 분석 | `calcSensitivityGrid()` (offsetEffect.ts:1174) | 이진 탐색으로 가격 시나리오별 BEP 물량 역산, 15회 반복 수렴 |

#### 3) Opus 프롬프트 COLUMN_MAP 검증 — 이미 파싱됨
Opus가 제안한 `COLUMN_MAP`의 모든 필드가 기존 TypeScript 타입에 매핑됨:
- `qty_actual` → `ItemProfitabilityRecord.매출수량` (number)
- `vc_material` ~ `vc_sample` (14종 변동비) → `ItemProfitabilityRecord.원재료비`...`견본비` (number)
- `fc_labor/depreciation/other` (3종 고정비) → `ItemProfitabilityRecord.제조고정노무비/감가상각비/기타경비`
- `contribution_margin` → `ItemCostDetailRecord.공헌이익` (PlanActualDiff)
- 추가: `offsetEffect.ts:buildVariableCostRatioMap()` (line 217)이 이미 200 보고서의 14개 변동비를 사용하여 변동비율 맵 구축 완료

#### 4) Opus 프롬프트의 관리회계 로직 검증 — 부분 수정 필요
| 항목 | Opus 제안 | 검증 결과 |
|------|----------|----------|
| 공헌이익 계산 | `매출액 - 변동비총합 - 직접판매운반비` | ✅ 정확. 기존 `calcCustomerItemCVP()`(line 293-300)에서 `mfgVC + sgaVC`로 동일 계산 |

### 보완 3: 회귀 모델을 쌍곡선으로 확장
**1차 계획**: 선형 회귀 `단위원가 = a + b × 수량`만 포함
**보완**: Opus 4.7 제안대로 **쌍곡선 회귀** `단위원가 = a + b × (1/수량)` 추가

**경제학적 근거**: 단위 고정비 = FC/Q → 수량의 역수에 비례하는 감소 함수. 선형보다 이론적으로 정확.

```typescript
export function calcVolumeUnitCostRegression(
  rawItemProfitability: ItemProfitabilityRecord[],
  options?: {
    minDataPoints?: number;      // default 3
    excludeRawMaterial?: boolean; // 원재료비 제외 (가격효과 분리)
    model?: "linear" | "hyperbolic" | "both"; // default "both"
  }
): RegressionSummary;
```

**듀얼 회귀 결과**:
- 쌍곡선 R² vs 선형 R² 비교 → 어느 모델이 데이터에 더 적합한지 자동 판정
- UI에 두 회귀선 겹쳐 표시 (실선=쌍곡선, 점선=선형)
- Opus 판정 기준 그대로 적용: R² > 0.5 & b > 0 → 부분 지지 / R² < 0.3 → 기각

export interface ContributionRedFlag {

export function calcContributionRedFlags(

  thresholds?: { greenMin: number; yellowMin: number } // default 10%, 0%

```

**데이터 소스**: 
- CVPItem[]: 100 보고서 기반 거래처×품목별 공헌이익 (page.tsx에서 계산, 두 탭이 공유)
- rawItemProfitability: 200 보고서 월별 데이터 (sparkline 트렌드용)

**트래픽라이트 기준** (Opus 4.7 로직 + 보정):
- 🟢 Green: CM% ≥ 10% → 고정비 회수 기여 가능
- 🟡 Yellow: 0% ≤ CM% < 10% → Marginal, 추가 분석 필요 (Opus 기준 5%에서 10%로 상향 — 건자재 업종 특성)
- 🔴 Red: CM% < 0% → 팔수록 손해. **사업부 주장 자동 기각**

**월별 트렌드 계산**:
- rawItemProfitability에서 품목별 그룹 → 월별 `(매출액 - Σ변동비) / 매출액` 계산
- 최근 3개월 추세: 연속 하락 → "deteriorating", 연속 상승 → "improving", 그 외 → "stable"

  // 선형 회귀: unitCost = a + b × quantity
  linear: { slope: number; intercept: number; rSquared: number };
  // 쌍곡선 회귀: unitCost = a + b × (1/quantity) [경제학적 모델]
  hyperbolic: { a: number; b: number; rSquared: number };
  // 판정
  bestModel: "linear" | "hyperbolic";       // R² 높은 쪽
  bestRSquared: number;
  isSignificant: boolean;                    // bestR² > 0.3 && pointCount >= 3
  hypothesisSupport: "support" | "partial" | "reject";
  interpretation: string;                    // 한국어 1줄 판정
}

export interface RegressionSummary {
  totalItems: number;
  significantCount: number;
  supportCount: number;        // 수량↑ → 원가↓ 관계 유의미
  rejectCount: number;
  avgBestRSquared: number;
  items: RegressionResult[];
}

export function calcVolumeUnitCostRegression(
  rawItemProfitability: ItemProfitabilityRecord[],
  options?: {
    minDataPoints?: number;           // default 3
    excludeRawMaterial?: boolean;     // 원재료비 제외 회귀 (가격 효과 분리)
    model?: "linear" | "hyperbolic" | "both";  // default "both"
  }
): RegressionSummary;
```

**OLS 구현** (순수 TypeScript, ~40줄):
- 선형: `slope = (nΣxy - ΣxΣy) / (nΣx² - (Σx)²)`, `R² = 1 - SS_res/SS_tot`
- 쌍곡선: X를 `1/quantity`로 치환 → 동일 OLS 적용 (`b > 0`이면 수량↑→원가↓ 지지)
- 수학적 검증: `총원가 = a×수량 + b` 형태 → a=한계비용(변동비 단가), b=총고정비. 경제학적으로 정확.
- 라이브러리 불필요 — 클라이언트 번들 사이즈 보존

**엣지케이스 필터**:
- `매출수량 = 0` → `1/0 = Infinity` → **자동 제외**
- `매출수량 < minQuantity(default 10)` → 이상치 회귀 왜곡 방지를 위해 제외
- 단일 품목 데이터포인트 < minDataPoints → "데이터 부족" 판정, 회귀 스킵

**원재료비 제외 옵션** (Opus 요구사항):
- `excludeRawMaterial: true` 시 단위원가 = `(실적매출원가 - 원재료비 - 부재료비) / 매출수량`
- 이란전쟁 등 외부 원재료 가격 변동 효과를 분리하여 순수 고정비 분산 효과만 검증

**판정 기준** (Opus 4.7 기준 적용):
- R² > 0.5 & 올바른 방향(선형: slope < 0, 쌍곡선: b > 0) → `"support"` 
- 0.3 < R² ≤ 0.5 → `"partial"`
- R² ≤ 0.3 또는 방향 반대 → `"reject"` (사업부 주장 기각)

  totalSim: TotalViewSimulation,
  capacityCheck?: { alertLevel: string },

}

### 알려진 한계 (UI에 명시)

| 한계 | 영향 | 대응 |
|------|------|------|
| 회귀 자기상관(Autocorrelation) | 월별 데이터 인접 포인트 상관 → R² 과대추정 가능 | 비즈니스 대시보드 수준에서 허용, 학술 논문 아님 |
| 계절성(Seasonality) | 건자재 성수기(3~10월)에 생산 집중 → 회귀 교란 | `excludeRawMaterial` 옵션으로 원재료 가격 변동 분리 |
| 원가 배부 기준 변경 | ERP 배부 로직 변경 시 시계열 단절 | 데이터 구간 일관성 전제, UI에 "ERP 설정 기준" 고지 |
| 생산량 ≠ 판매량 | 재고 버퍼로 인한 차이 | Capacity 추정에 15% 마진 + 듀얼 소스 + 신뢰도 등급 |
| 공유 생산라인 | 한 품목 증산이 다른 품목 감산으로 이어질 수 있음 | 풀 단위(대분류) 분석으로 부분 해결. 완전 해결은 MRP 데이터 필요 |
