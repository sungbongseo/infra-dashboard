## 8. Lessons Learned (PDCA)

### 8.1 잘된 점 (Keep)

- **사용자 선택지 명시화**: 3개 옵션(A/B+/C) + 보너스 범위 + 기본 상태 처리를 AskUserQuestion으로 분리 질문해 의사결정 오해 방지
- **기존 자산 재활용**: 신규 함수 0개, 신규 타입 0개. 30 LOC 경량 패치로 효과 극대화
- **옵셔널 파라미터 패턴**: 끝에 `?:` 추가로 breaking change 회피. API 확장의 표준 패턴
- **증거 기반 완료**: git diff, Grep, 빌드/테스트 출력 모두 Analysis 문서에 file:line 근거 인용
- **Pre-existing 실패 식별**: `git stash` 전후 테스트 결과 비교로 이번 변경 책임 분리

### 8.2 개선할 점 (Problem → Try)

- **Agent rate limit 대응**: gap-detector agent 호출 1회 rate limit 도달 → 직접 분석으로 대체. 장기 세션에서 agent 호출을 여러 단계로 나누거나 핵심 단계만 agent에 위임하는 전략 필요
- **수동 QA 자동화 부재**: 5개 시나리오를 E2E 테스트(Playwright)로 자동화하면 회귀 방어 강화 가능 — 별도 사이클로 고려
- **Plan 파일 경로 이원화**: bkit 규약(`docs/01-plan/features/`) vs Claude Code Plan mode(`~/.claude/plans/`) 간 경로 불일치. 통합 규약 필요

### 8.3 재발 방지 (Try Next)

- **단일 진실 소스 원칙**: 유사 패턴(요약 뷰 + 상세 뷰) 발견 시 "상태 공유 + 배지 노출" 패턴 재적용 검토
- **옵셔널 파라미터 우선**: API 확장 시 breaking change가 필요해 보여도 먼저 옵셔널로 추가하고 기본값 폴백으로 동작하는지 검토
