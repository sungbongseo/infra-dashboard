## 2. Background & Problem

### 2.1 원래 요구사항
건자재사업본부에서 **"물량을 늘리면 고정비 분산으로 단위원가가 낮아지므로, 특정 품목은 저가수주를 해도 가동률이 오르면 전체 이익이 난다"**는 가정이 통용 중이나, 이를 검증할 분석 기능이 없었음.

### 2.2 Opus 4.7 프롬프트 분석
Claude Opus 4.7에게 상황을 설명하고 받은 개발 프롬프트는 6가지 분석 기능을 **Python/Streamlit 별도 대시보드**로 구현할 것을 제안. 정밀 분석 결과:

| 분석 항목 | 결과 |
|----------|------|
| 기술 스택 | **기각** — 기존 Next.js에 통합 (5종 데이터 이미 파싱 완료) |
| 6개 기능 중 3개 | **이미 존재** — F2 BEP, F4 증분분석, 감도분석은 offsetEffect.ts에 더 정교하게 구현됨 |
| 관리회계 로직 | **대부분 정확** — 쌍곡선 회귀 모델 채택, Capacity 프록시 한계 보완 |
| COLUMN_MAP | **100% 매핑** — 기존 TypeScript 타입에 모든 필드 존재 |

## 3. Implementation Details

### 3.1 Architecture Decision

**기존 OffsetEffectTab(2,464줄)을 확장하지 않고 독립 탭 "가설 검증" 신설.**

근거:
- OffsetEffectTab은 CVP 시뮬레이터로서 완결성 보유
- 4가지 신규 분석은 "가설 검증 워크플로우"라는 별도 목적
- 수익성 분석 페이지에 5번째 탭 그룹 추가 (기존 4개 그룹 유지)

### 3.2 New Files

| 파일 | 줄 수 | 역할 |
|------|:-----:|------|
| `src/lib/analysis/lowPriceVerification.ts` | 887 | F1 Red-Flag + F3 쌍곡선/선형 듀얼 회귀 + F5 Capacity + F6 Cannibalization + 종합 판정 |
| `src/lib/analysis/lowPriceVerification.test.ts` | 455 | 22개 단위 테스트 (분류 정확도, OLS 수학 검증, 경고 threshold, 종합 판정) |

| `OffsetEffectTab.tsx` | Props 확장 (CVP fallback, manufacturingCost, onNavigate) + "가설 검증 탭 →" 교차 링크 |

### 3.4 Key Technical Decisions

| 결정 | 선택 | 근거 |
|------|------|------|
| Python 별도 대시보드 vs 기존 통합 | **기존 Next.js에 통합** | 5종 파일 이미 파싱 완료, 별도 스택 유지보수 불가 |
| OLS 라이브러리 vs 인라인 구현 | **인라인 ~30줄** | 클라이언트 번들 사이즈 보존, 단순 선형회귀에 외부 의존성 불필요 |
| 회귀 모델 | **쌍곡선 + 선형 듀얼** | 쌍곡선이 경제학적으로 정확 (단위원가 = a + b/수량 → 총원가 = a×수량 + b) |
| Cannibalization CV | **수량 가중 CV** | 대량 저가 거래가 소량보다 더 위험 — 단순 CV보다 정확 |
| Capacity 추정 | **듀얼 소스 × 1.15** | 제조원가(Q1/3) + 판매실적(max) 중 큰 값 + 15% headroom |
| CVP 데이터 공유 | **page.tsx 호이스팅** | 두 탭 간 중복 계산 제거, 동일 데이터 보장 |
| OffsetEffectTab 호환 | **props fallback** | 새 props 없이도 내부 계산 100% 동작 |
