# Plan: 저가수주 판단기 — 1화면 의사결정 도구

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 기존 OffsetEffectTab(6 Step, 18개 컨트롤, 2700줄)이 분석가용 도구이지 영업용 도구가 아님. 영업 과장이 "이 저가수주 해도 되나?"에 대한 YES/NO 답을 얻으려면 20분 이상 소요 |
| **Solution** | OffsetEffectTab 최상단에 "저가수주 판단기" 1화면 카드를 삽입. 입력 4개(품목/거래처/수량/단가) → YES/NO + 이유 3줄 + 감도분석 1줄. 기존 Step 1~5는 "상세 분석" 접기로 이동 |
| **Function UX Effect** | 영업 과장이 5분 → **30초**에 의사결정. 입력 18개 → **4개**. 스크롤 없이 1화면에서 결론 확인 |
| **Core Value** | "현미경 사진" 대신 "진단서 1장" — 분석 정확도는 유지하면서 접근성을 극적으로 개선 |

---

## 1. 배경

### 자기 검증에서 발견한 문제
- OffsetEffectTab: 18개 useState, 6 Step, 2700줄 → 분석가/개발자용 도구
- 영업 과장의 실제 워크플로우: 품목 검색(10초) → 슬라이더 조작(30초, 모르겠음) → verdict 스크롤(45초) → 혼란 → 스프레드시트로 복귀
- LowPriceVerifyTab: 가설 검증이라는 학술적 목적이지 의사결정 도구가 아님
- 결론: **분석은 맞지만 포장이 틀렸다**

### 설계 원칙
1. **5초 답변**: 스크롤 없이 YES/NO가 보여야 함
2. **입력 최소화**: 영업 과장이 아는 것만 입력 (품목, 거래처, 예상 수량, 제안 단가)
3. **이유 설명**: 왜 YES/NO인지 3줄 이내 (수식 아닌 한국어)
4. **상세는 숨기기**: 기존 분석은 삭제하지 않고 접기(details)로 보존

### 2.2 입력 (4개만)

| 입력 | 소스 | 기본값 |
|------|------|--------|
| 품목 | cvpItems에서 추출한 품목 리스트 (기존 combobox 재사용) | null (필수) |
| 거래처 | cvpItems에서 추출한 거래처 리스트 | null (전체 = 모든 거래처) |
| 예상 추가수량 | 숫자 input (절대 수량) | 0 |
| 제안 단가 | 숫자 input (원/단위) → 현재 단가 대비 % 자동 계산 | 현재 단가 |

**기존 18개 입력과의 관계**:
- `targetItem` ← 품목 선택
- `targetCustomer` ← 거래처 선택
- `volumeAbsolute` ← 예상 추가수량
- `priceChangePct` ← (제안 단가 / 현재 단가 - 1) × 100 (자동 계산)
- 원가 슬라이더 3개 → 0%로 고정 (단가 변동만 고려, 원가 인상은 별도 시나리오)
- 풀 설정, CVP 그룹, 입력 모드 등 → 자동 결정

### 2.3 판정 로직

```typescript
function calcQuickVerdict(input): QuickVerdict {
  // 1. 기존 calcTotalViewSimulation 실행 (4a)
  const sim4a = calcTotalViewSimulation({ ... });
  
  // 2. 기존 calcComprehensiveVerdict 실행 (4a+4b 자동 연동)
  const comp = calcComprehensiveVerdict(sim4a, itemProfitability, targetItem, ...);
  
  // 3. 거래처 포트폴리오 계산
  const portfolio = calcCustomerPortfolioOffset(cvpItems, targetItem, targetCustomer);
  
  // 4. 감도분석: 최소 필요 수량 역산 (기존 calcSensitivityGrid 활용)
  const minVolume = findMinBreakevenVolume(sim4a, ...);
  
  // 5. 3단계 판정
  return {
    // 판정 기준:
    // ✅ APPROVE: comp.comprehensiveNet > 0 OR portfolio에서 거래처 순마진 양수
    // ❌ REJECT: sim4a.netEffect < 0 AND comp.comprehensiveNet < 0 AND portfolio 순마진 음수
    // ⚠️ CONDITIONAL: 나머지 (일부 조건에서만 이득)
    verdict: "approve" | "reject" | "conditional",
    
    // 3가지 관점 금액
    singleItemEffect,    // 4a 단독
    poolOthersGain,      // 4b 풀 덤 효과
    portfolioOtherCM,    // 거래처 포트폴리오
    
    // 한국어 이유 (3줄 이내)
    reason: string,
    
    // 감도: 최소 필요 수량
    minRequiredVolume: number | null,
    isVolumeEnough: boolean,
  };
}
```

**핵심**: 새로운 분석 로직은 만들지 않음. **기존 함수를 조합**하여 3가지 관점을 하나의 판정으로 통합.

### 2.5 기존 입력 상태 연동

판단기에서 입력한 값이 상세 분석(기존 Step)에도 자동 반영:
- 품목/거래처 선택 → 기존 targetItem/targetCustomer 상태 동기화
- 추가수량 → volumeAbsolute 동기화
- 제안 단가 → priceChangePct 자동 계산 동기화
- "상세 분석 보기" 펼치면 이미 해당 시나리오가 설정된 상태
