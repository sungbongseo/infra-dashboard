# Phase A 수동 QA 체크리스트 (브라우저 기반)

**대상**: v2 Phase A 완료 후 경영진 승인 전 검증
**소요**: 약 15-20분
**환경**: `npm run dev` 후 `/dashboard/profitability` → "저가수주 상계효과" 탭

## 🧪 시나리오 1: 회귀 검증 (Phase A 전과 동일 동작)

**조건**: 원가 슬라이더 모두 0, Monte Carlo 토글 OFF

- [ ] 판단기 품목 선택 → 3카드 그리드 표시 정상 (단독/풀/포트폴리오)
- [ ] 판정 문구/색상이 기존과 동일
- [ ] 3카드 아래 **💡 단위공헌이익 배너** 신규 노출 (이전엔 없던 것)
- [ ] "원가 반영 중" 앰버 배지 미표시 (슬라이더 0이므로)
- [ ] 🎲 Monte Carlo 체크박스 OFF 상태

## 🧪 시나리오 2: WS3 단위공헌이익 노출

- [ ] 품목 + 거래처 + 추가수량 + 제안단가 입력 → **💡 배너** 자동 표시
- [ ] 공헌이익 = (제안단가 − 변동비) 공식 표시 확인
- [ ] 추가수량 변경 시 "물량 기여" 값이 실시간 재계산
- [ ] Step 4a 원가 슬라이더 조작(예: 원재료 +10%) → "원가 조정 결과" 블록에 **"조정 후 단위공헌이익"** 1줄 추가 표시
- [ ] 단위마진 음수 + 공헌이익 양수일 때 **"박리다매 여지 존재"** 배지 자동 노출 확인

## 🧪 시나리오 3: WS1 Monte Carlo

- [ ] 🎲 체크박스 ON → 0.5-1초 후 4창 표시
  - [ ] **평균 기대값** (손익 부호별 색상)
  - [ ] **95% 신뢰구간** (p5 ~ p95)
  - [ ] **손실 확률** (10%↓ 녹색 / 30%↓ 앰버 / 30%+ 적색 자동 전환)
  - [ ] **표준편차 σ + 5,000회 시뮬 표기**
- [ ] Step 4a 원가 슬라이더 조작 → MC 결과 실시간 재계산
- [ ] 200 보고서 없는 품목 선택 시 "폴백 σ 사용 중" 경고 표시
- [ ] 판단기 입력 변경 시 결정론적(같은 입력 = 같은 결과) 확인

## 🧪 시나리오 4: WS2 캐파 Step-up 경고

- [ ] 수불현황 파일 업로드된 품목 선택 → 🏭 **생산 캐파 분석** 블록 자동 표시
- [ ] 공장명 + 관측 개월수 표기 확인
- [ ] Gauge bar: 80% 기준선 + 100% 기준선 표시
- [ ] 자동 제안값 = 과거 월별 max × 110%
- [ ] 추가수량을 점점 늘려 사용률 상승 시나리오:
  - [ ] <80%: ok, 녹색
  - [ ] 80-90%: caution, 앰버
  - [ ] 90-100%: warning, 오렌지 + "Step-up 임박" 경고
  - [ ] ≥100%: severe, 적색 + **숨겨진 투자비 경고** 배너 + "신규 라인 N개 필요" 메시지
- [ ] ⚙️ 수동 조정 펼치기 → 캐파/라인당 고정비/라인당 증산능력 직접 입력 가능
- [ ] 수동 조정 후 breach 레벨 재판정 즉시 반영

## 🧪 시나리오 5: 통합 End-to-End (경영진 데모용)

**실제 저가수주 건 1건 입력**:
예) 품목: Black Top Sheet(2.0mm*10m)_옥천, 추가수량: 5,500 ROL, 제안단가: 50,675원

- [ ] 3카드 + 💡 공헌이익 + 🏭 캐파 + 🎲 MC 모두 노출
- [ ] 전체 화면 스크린샷 캡처 → 경영진 발표 자료로 활용
- [ ] 원가 슬라이더 원자재 +50% 시나리오 → 4개 영역 모두 실시간 업데이트 확인

## 🧪 시나리오 6: 엣지 케이스 방어

- [ ] 품목만 선택, 수량/단가 미입력 → 판정 영역 숨김 (정상)
- [ ] 수량 0 또는 음수 → 계산 방어 (NaN 없음)
- [ ] 200 보고서 미업로드 + 캐파 조작 → 에러 없이 폴백 동작
- [ ] 수불현황 미업로드 → 🏭 캐파 블록 미노출 (정상)
- [ ] 단위공헌이익 음수 품목 선택 → "BEP 도달 불가" 안내

## 🧪 시나리오 7: 성능 (실무 기준)

- [ ] 첫 탭 진입 → 500ms 이내 렌더 완료
- [ ] MC 토글 ON → 1.5초 이내 4창 표시 (5k 시뮬)
- [ ] 슬라이더 드래그 → 60fps 유지 (끊김 없음)
- [ ] 메모리 사용량 → 200MB 이하 (DevTools 확인)
